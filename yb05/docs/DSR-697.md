Initialisation des données de répartition à partir du fichier CSV
Chargement initial du référentiel des PDI
En tant que

TRPPU,

Je souhaite

charger le fichier CSV des clés de répartition fourni par le métier dans la table TRPPU_CLES_REPARTITION

Afin de

constituer le référentiel source des PDI, de leurs rattachements sites et de leurs trafics utilisé pour le calcul des clés de répartition.

Contexte

Le métier fournit un fichier CSV contenant l'ensemble des PDI actifs et leurs informations de rattachement :

identifiant PDI ;
PDI de rattachement ;
trafic colis ;
trafic OO ;
trafic 3S ;
potentiel IP ;
informations de site ;
informations d'établissement ;
informations DEX.

Ce fichier constitue la photographie initiale du référentiel TRPPU.

Les données chargées doivent être historisées afin de permettre la reconstruction des calculs utilisés dans les différents scénarios.

Table cible
TRPPU_CLES_REPARTITION

Structure :

 
TRPPU_CLES_REPARTITION
(
    id,
    id_pdi,
    pdi_rattache,
 
    trafic_colis,
    trafic_oo,
    trafic_3s,
    potentielip,
 
    nature,
    co_regate_site,
    type_site,
    lb_regate,
 
    co_regate_etablissement,
    lb_etablissement,
 
    co_regate_dex,
    lb_dex,
 
    nb_pre,
 
    id_referentiel,
 
    date_debut_validite,
    date_fin_validite
)
 

Règles de gestion
RG1

Le chargement correspond à un référentiel unique.

Exemple :

Référentiel n°1

Tous les enregistrements chargés reçoivent :

id_referentiel = 1

RG2

Toutes les lignes importées sont considérées comme actives.

Les valeurs suivantes sont renseignées :

 
date_debut_validite = date du chargement
date_fin_validite = NULL
 

RG3

Les champs vides suivants doivent être convertis en NULL :

 
co_regate_etablissement
lb_etablissement
nb_pre
potentielip
 

RG4

Les doublons strictement identiques présents dans le fichier doivent être éliminés avant chargement.

Un doublon est défini comme :

 
Même PDI
+
Même site
+
Même trafic colis
+
Même trafic OO
+
Même trafic 3S
+
Même potentiel IP
 

RG5

Le chargement ne doit pas créer plusieurs fois le même PDI pour un même référentiel.

La règle d'unicité est :

(id_pdi, id_referentiel)

RG6

Le chargement est réalisé dans le référentiel cible après suppression des données éventuellement déjà présentes pour le référentiel à charger.

Préparation du fichier
Étape 1

Réception du fichier métier.

Exemple :

cles_repartitions_final_joined.csv

Étape 2

Déduplication des données.

Exemple avec "DuckDB" :

 
COPY (
    SELECT DISTINCT *
    FROM read_csv_auto(
        'cles_repartitions_final_joined.csv'
    )
)
TO 'cles_repartitions_final_joined_ref1.csv'
(
    FORMAT CSV,
    HEADER,
    DELIMITER ';'
);
 

Étape 3

Dépôt du fichier sur le serveur MySQL.

Exemple :

/var/lib/mysql-files/

Fichier :

cles_repartitions_final_joined_ref1.csv

Traitement d'initialisation
Étape 1

Nettoyer les données déjà présentes pour le référentiel concerné.

 
DELETE
FROM trppu_cles_repartition
WHERE id_referentiel = 1;
 

Étape 2

Charger le fichier CSV.

 
LOAD DATA INFILE
'/var/lib/mysql-files/cles_repartitions_final_joined_ref1.csv'
INTO TABLE trppu_cles_repartition
CHARACTER SET utf8mb4
FIELDS TERMINATED BY ';'
OPTIONALLY ENCLOSED BY '"'
LINES TERMINATED BY '\n'
IGNORE 1 ROWS
(
    id_pdi,
    pdi_rattache,
    trafic_colis,
    trafic_oo,
    trafic_3s,
    nature,
    co_regate_site,
    type_site,
    lb_regate,
    @regate_etab,
    @libelle_etab,
    co_regate_dex,
    lb_dex,
    @nb_pre,
    @potentielip
)
SET
    co_regate_etablissement = NULLIF(@regate_etab,''),
    lb_etablissement = NULLIF(@libelle_etab,''),
    nb_pre = NULLIF(@nb_pre,''),
    potentielip = NULLIF(@potentielip,''),
 
    id_referentiel = 1,
    date_debut_validite = CURRENT_DATE(),
    date_fin_validite = NULL;
 

Contrôles de cohérence
Contrôle 1

Le nombre de lignes chargées est identique au nombre de lignes du fichier après déduplication.

 
SELECT COUNT
FROM trppu_cles_repartition
WHERE id_referentiel = 1;
 

Contrôle 2

Aucun doublon de type :

 
(id_pdi, id_referentiel)
 

n'est présent.

 
SELECT
    id_pdi,
    COUNT(*)
FROM trppu_cles_repartition
WHERE id_referentiel = 1
GROUP BY id_pdi
HAVING COUNT(*) > 1;
 

Résultat attendu :

0 ligne

Contrôle 3

Toutes les lignes du référentiel sont actives.

 
SELECT COUNT
FROM trppu_cles_repartition
WHERE id_referentiel = 1
AND date_fin_validite IS NOT NULL;
 

Résultat attendu :

0 ligne

Critères d'acceptation
CA1

Le chargement importe l'ensemble des PDI du fichier métier.

CA2

Les doublons strictement identiques sont éliminés avant chargement.

CA3

Chaque ligne est associée au référentiel chargé.

CA4

Les champs métier vides sont stockés à NULL.

CA5

Toutes les lignes sont créées avec une date de début de validité renseignée.

CA6

Toutes les lignes sont créées avec une date de fin de validité à NULL.

CA7

La table peut ensuite être utilisée pour générer :

les agrégats de trafic par site (TRPPU_SITE_TRAFIC) ;
les clés de répartition (TRPPU_CLE_REPARTITION) ;
les scénarios TRPPU.
Bénéfice

Cette initialisation constitue le point d'entrée de la chaîne de calcul :

 
Fichier CSV métier
        ↓
TRPPU_CLES_REPARTITION
        ↓
TRPPU_SITE_TRAFIC
        ↓
TRPPU_CLE_REPARTITION
        ↓
TRPPU_SCENARIO
 

et garantit la traçabilité complète des données utilisées dans les futurs scénarios TRPPU.
