User Story

En tant qu'exploitant DSR

Je souhaite disposer d'un batch permettant de déployer, mettre à jour et restaurer automatiquement les objets de base de données TRPPU

Afin de sécuriser les mises en production, industrialiser les évolutions de schéma et garantir la traçabilité complète des opérations réalisées.

Objectif

Le batch de mise à jour de base de données TRPPU dsr_trppu_maj_bd.py permet :

l'initialisation complète de la base TRPPU lors de la première mise en production ;
l'application des évolutions de schéma lors des versions suivantes ;
le chargement des données d'initialisation ;
la création ou modification des objets SQL ;
le rollback des évolutions ;
la traçabilité de toutes les opérations exécutées.

Le batch constitue l'unique mécanisme autorisé pour déployer des évolutions de structure de la base TRPPU.

Principe général

Le batch reçoit en paramètre une version de déploiement :

python dsr_trppu_maj_bd.py  --version TRPPU_V1.1.0

Le batch :

vérifie l'environnement ;
vérifie la connexion à la base ;
lit le fichier de configuration associé à la version ;
exécute les scripts dans l'ordre demandé ;
met à jour les tables de suivi ;
journalise les opérations ;
exécute un rollback en cas d'erreur.
Responsabilités du batch

Le batch doit permettre :

Création d'objets
tables ;
vues ;
procédures stockées ;
contraintes ;
index.
Modification d'objets
ajout de colonnes ;
suppression de colonnes ;
modification de colonnes ;
évolution des index ;
évolution des contraintes.
Initialisation
chargement de données de référence ;
chargement de données fonctionnelles nécessaires au démarrage.
Rollback
retour arrière d'une version de déploiement.
Hors périmètre

Le batch ne doit pas gérer :

le déploiement des composants Java ;
le déploiement des composants Angular ;
les déploiements OpenShift ;
les traitements métiers TRPPU ;
les opérations manuelles DBA.

Ordre d'exécution par défaut

Par défaut les étapes sont exécutées dans l'ordre suivant :

1.tables
2. vues
3. procedures
4. contraintes
5. index
6. initialisation

Le fichier YAML peut surcharger cet ordre.

Exécution des scripts

Dans chaque sous-répertoire :

tables
contraintes
index
...

les scripts SQL sont exécutés par ordre alphabétique.

Exemple :

001_create_table.sql
002_create_table.sql
003_create_table.sql

Gestion des erreurs
Principe

Mode obligatoire :

STOP ON ERROR
Exemple :

001_create_table.sql
OK

002_create_table.sql
OK

003_create_table.sql
ERREUR

Conséquences :

arrêt immédiat du traitement ;
journalisation de l'erreur ;
exécution du rollback ;
mise à jour du statut batch.

Aucun script suivant ne doit être exécuté.

Gestion transactionnelle

Le mécanisme de rollback repose sur l'exécution explicite des scripts contenus dans le répertoire :

rollback

Le rollback ne repose pas sur une transaction globale de base de données.

Certaines opérations DDL pouvant être non transactionnelles selon le SGBD, chaque version livrée doit donc fournir les scripts de retour arrière nécessaires.

Gestion des réexécutions

avec :

alors :

l'exécution est refusée
sauf présence du paramètre :

Reprise après incident

Au démarrage le batch doit vérifier :

la dernière version exécutée ;
l'existence éventuelle d'un batch resté EN_COURS ;
la cohérence de l'état de la base.

En cas d'incohérence :

{{arrêt du traitement }}avec message explicite.

Critères d'acceptation
CA-01

Une base vide peut être initialisée entièrement via :

python dsr_trppu_maj_bd.py --version TRPPU_V1.0.0

CA-02

Une évolution de schéma peut être déployée via :

python dsr_trppu_maj_bd.py --version TRPPU_V1.1.0

CA-03

Le batch exécute les scripts dans l'ordre défini dans le fichier YAML.

CA-04

Toute erreur provoque :

arrêt du traitement
journalisation
rollback

CA-05

Chaque exécution est tracée :

dans Kibana ;
dans un fichier de log ;
dans TRPPU_SUIVI_BATCH ;
dans TRPPU_DB_VERSION.
CA-06

Une version déjà exécutée avec succès ne peut pas être rejouée sans l'utilisation explicite du paramètre :

--force

CA-07

Le batch permet l'exécution complète ou partielle d'une version selon le paramètre :

--step
