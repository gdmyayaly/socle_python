En tant que TRPPU

Je veux que les informations de variation du trafic prévisionnel des objets/produits d'un scénario soient mise à jour en base de données 

Afin de sauvegarder les variations des objets liée au scénario en cours et ce à chaque "modification"

Pour cela, créer un service dans le POD yb04 qui mettra à jour la table "trppu_scenario_variations_prev" avec l'ajout ou la modification ou la suppression de la variation du prévisionnel pour l'objet concerné.

Lorsque l'utilisateur "ajoute" une variation du trafic prévisionnel pour un objet, le service ajoute dans la table une ligne avec les informations suivante : 

id_scenario  > id du scénario "en cours" pour lequel la variation du trafic prévisionnel du produit est pris en compte
co_produit   > code du produit dont le trafic est modifié par la variation définie par l'utilisateur
variation_pct  > variation en % du trafic du produit concerné pour le scénario
dt_creation   > date d'ajout /modification de la variation du trafic du produit
id_rh   > id_rh crypté de l'utilisateur ayant ajouté/modifié la variation de trafic pour le produit

Lorsque l'utilisateur modifie la variation de trafic du produit, le service mettra à jour les informations ci-dessous de la même table pour l'id du scénario en cours et le produit concerné :

variation_pct   > avec la nouvelle valeur (%) de variation 
dt_creation > la date de modification = date du jour
id_rh > id_rh crypté de l'utilisateur ayant ajouté/modifié la variation de trafic pour le produit

Lorsque l'utilisateur supprimera variation de trafic du produit, c'est à dire lorsqu'il repasse la variation de trafic à 0%, soit la valeur par défaut, le service supprimera dans la même table la ligne pour l'id du scénario en cours et le produit concerné.




Critères d'acceptances : 

Dans l'IHM des paramètres de variation des trafics prévisionnels : 

augmenter de 25% le trafic des OO et vérifier en base qu'une ligne a bien été ajoutée dans la table "trppu_scenario_variations_prev" avec les informations suivantes :
id_scenario = id du scénario concerné
co_produit = code produit des OO
variation_pct = 25%
dt_creation = date du jour
id_rh = id rh crypté
tester une valeur négative : diminuer de -15% le trafic des IP et vérifier en base qu'une ligne a bien été ajoutée dans la table "trppu_scenario_variations_prev" avec les informations suivantes :
id_scenario = id du scénario concerné
co_produit = code produit des IP
variation_pct = -15%
dt_creation = date du jour
id_rh = id rh crypté
Modifer la variation des OO qui était à 25% pour la passer à 40% et vérifier en base dans la table "trppu_scenario_variations_prev" que la ligne des OO pour le scénario a bien été modifiée avec les informations suivantes :
variation_pct = 40%  > (nouvelle valeur)
dt_creation = date du jour
id_rh = id rh crypté
Supprimer la variation des OO qui est à 40% en la repassant à 0% et vérifier en base dans la table "trppu_scenario_variations_prev" que la ligne des OO pour le scénario n'existe plus
