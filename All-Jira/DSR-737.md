Objectif

Mettre à disposition un service permettant de restituer la liste des Agrébals et des PDI associés :

à un scénario TRPPU ;
ou à un site identifié par son code REGATE.

Ce service a vocation à être utilisé par les fonctionnalités d'analyse, de diagnostic, de contrôle, d'audit et de support.

User Story

En tant que TRPPU

Je souhaite consulter les Agrébals et les PDI associés à un scénario ou à un site

Afin d'identifier précisément les éléments utilisés dans les calculs et les recalculs de trafic.

Contexte

Les Agrébals sont composés de plusieurs PDI.

Lors des analyses fonctionnelles ou des investigations, il est nécessaire de pouvoir identifier :

les Agrébals associés à un scénario ;
les Agrébals associés à un site ;
les PDI rattachés à chaque Agrébal.

Le service doit restituer la structure complète :

 
Agrébal
↓
Liste des PDI associés
 

Périmètre

Cette US couvre :

la création du service ;
la recherche par scénario ;
la recherche par site ;
la restitution des Agrébals ;
la restitution des PDI rattachés à chaque Agrébal.

Cette US ne couvre pas :

les calculs de trafic ;
les recalculs ;
la modification des données ;
les traitements batch.
Fonctionnement du service

Le service doit supporter deux modes de recherche.

Recherche par scénario
Entrée




{ "idScenario": 12345 }

Principe de recherche

Le service doit restituer les données réellement utilisées par le scénario.

Les données doivent être recherchées à partir :

du référentiel associé au scénario ;
de la version de clés utilisée ;
des données historisées associées au scénario.

Les données restituées ne doivent donc pas être limitées aux seules données actives.

Le service doit permettre de retrouver exactement les Agrébals et les PDI ayant servi aux calculs du scénario.

Recherche par site
Entrée




{ "codeRegate": "372920" }




Principe de recherche

Le service restitue uniquement les données actuellement actives.

Critères :

 
DATE_FIN_VALIDITE IS NULL
 

ou tout mécanisme équivalent permettant d'identifier les données actives.

Format de réponse
Exemple

 
{
"codeRegate": "372920",
"libelleSite": "SORIGNY PDC1",
"agrebals": [

{ "agrebalUuid": "AGREBAL-001", "pdis": [ 100005554, 100011320, 10004389 ] }

,

{ "agrebalUuid": "AGREBAL-002", "pdis": [ 100075421, 100087456 ] }

]
}
 
 

Données restituées
Informations site

 
CODE_REGATE
LIBELLE_SITE
 

Informations Agrébal

 
AGREBAL_UUID
 

ou l'identifiant fonctionnel retenu dans TRPPU.

Informations PDI

Pour chaque Agrébal :

 
ID_PDI
 

La restitution doit être organisée sous forme hiérarchique :

 
Agrébal
├─ PDI 1
├─ PDI 2
└─ PDI 3
 

Gestion des données historisées
Recherche par REGATE

Le service restitue exclusivement les données actives.

Exemple :

 
DATE_FIN_VALIDITE IS NULL
 

Recherche par scénario

Le service restitue les données associées au scénario.

Les données historisées doivent être prises en compte lorsque le scénario utilise :

une ancienne version de référentiel ;
une ancienne version de clés ;
des Agrébals historiques.

L'objectif est de pouvoir reconstituer exactement les éléments utilisés lors du calcul du scénario.

Cas particulier : scénario inexistant

Si le scénario n'existe pas :

 
Aucune donnée retournée.
 

Message explicite :

 
Scénario introuvable.
 

Cas particulier : site inexistant

Si le code REGATE n'existe pas :

 
Aucune donnée retournée.
 

Message explicite :

 
Site introuvable.
 

Journalisation

Tracer dans Kibana :

 
Type de recherche
 
Recherche par scénario
ou
Recherche par site
 
Paramètre fourni
 
Nombre d'Agrébals retournés
 
Nombre de PDI retournés
 
Durée du traitement
 

Règles de gestion
RG-001

Le service doit permettre une recherche par :

 
ID_SCENARIO
 

ou :

 
CODE_REGATE
 

RG-002

Une recherche par site restitue uniquement les données actives.

RG-003

Une recherche par scénario restitue les données réellement utilisées par le scénario, y compris les données historisées.

RG-004

La restitution doit être organisée par Agrébal.

RG-005

Pour chaque Agrébal, le service doit restituer la liste des PDI associés.

RG-006

Le service est en consultation uniquement.

Aucune modification de donnée n'est autorisée.

Critères d'acceptation
CA-01

Étant donné un scénario existant

Quand le service est appelé avec :

 
ID_SCENARIO
``
 

Alors les Agrébals utilisés par le scénario sont retournés avec leurs PDI associés.

CA-02

Étant donné un site existant

Quand le service est appelé avec :

 
CODE_REGATE
 

Alors les Agrébals actifs du site sont retournés avec leurs PDI associés.

CA-03

Étant donné un scénario utilisant des données historisées

Quand le service est appelé

Alors les Agrébals et PDI historiques utilisés par ce scénario sont retournés.

CA-04

Étant donné un scénario inexistant

Quand le service est appelé

Alors un message explicite est retourné.

CA-05

Étant donné un code REGATE inexistant

Quand le service est appelé

Alors un message explicite est retourné.

CA-06

Les données retournées permettent d'identifier précisément :

 
Scénario
↓
Agrébal
↓
PDI
 

pour les analyses fonctionnelles et les investigations de support.

Bénéfices attendus
Reconstitution exacte des données utilisées par un scénario.
Consultation des données actives d'un site.
Traçabilité des Agrébals et des PDI.
Aide aux analyses de recalculs.
Simplification des investigations fonctionnelles, techniques et de support.
