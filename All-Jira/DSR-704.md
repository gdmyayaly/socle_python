Objectif

Exécuter automatiquement l'ensemble de la chaîne de calcul des trafics pour un ou plusieurs scénarios avec un niveau de parallélisme configurable

User Story

En tant que exploitant TRPPU,

Je souhaite lancer le batch YB05 en mode ALL,

Afin de calculer automatiquement les trafics PDI et Agrébal des scénarios éligibles tout en utilisant au mieux les capacités du serveur grâce à un mécanisme de parallélisation configurable.

Objectif

Le mode :

 
YB05 ALL
 

constitue le mode nominal d'exploitation en production.

Le batch doit être capable de :

traiter un scénario unique passé en paramètre ;
traiter automatiquement tous les scénarios éligibles ;
exécuter plusieurs scénarios en parallèle ;
limiter le nombre de traitements simultanés grâce à une variable d'environnement.

Les règles métier existantes ne doivent pas être dupliquées.

Le mode ALL agit comme un orchestrateur qui appelle les traitements existants :

 
controleEligibiliteScenario()
 
calculTraficPdi()
 
calculTraficAgrebal()
 

Paramétrage du parallélisme
Variable d'environnement

Le nombre maximum de traitements simultanés est piloté par la variable :

 
NB_WORKER
 

Valeurs possibles

Exemples :

 
NB_WORKER=1
 

Traitement séquentiel.

 
NB_WORKER=2
 

Deux scénarios simultanés.

 
NB_WORKER=4
 

Quatre scénarios simultanés.

Valeur par défaut

Si la variable n'est pas définie :

 
NB_WORKER=1
 

Le batch fonctionne alors en mode séquentiel.

Modes d'exécution
Traitement automatique de tous les scénarios éligibles

 
YB05 ALL
 
Le batch recherche automatiquement :
 

les scénarios jamais calculés ;
les scénarios marqués pour recalcul.
 
Un scénario est considéré éligible lorsque :
 
STATUT = VALIDE
EST_FIGE = 1
CALCUL_TRAFIC_EN_COURS = 0
TRAFIC_PDI_CALCULE = 0
TRAFIC_AGREBAL_CALCULE = 0
 
Ces indicateurs peuvent correspondre :
 
à un premier calcul ;
à une demande de recalcul suite à un mouvement Agrébal ;
à une demande de recalcul suite à une évolution des clés ;
à une demande de recalcul manuel.
Traitement d'un scénario spécifique

 
YB05 ALL <id_scenario>
 

Exemple :

 
YB05 ALL 12345
 

Le parallélisme n'est alors pas utilisé puisque un seul scénario est concerné.

Recherche des scénarios éligibles

Les scénarios candidats sont recherchés dans :

 
TRPPU_SCENARIO
 

avec les critères :

 
STATUT = 'VALIDE'
EST_FIGE = 1
CALCUL_TRAFIC_EN_COURS = 0
TRAFIC_PDI_CALCULE = 0
TRAFIC_AGREBAL_CALCULE = 0
 

Exemple :

 
SELECT id_scenario
FROM trppu_scenario
WHERE statut = 'VALIDE'
AND est_fige = 1
AND calcul_trafic_en_cours = 0
AND trafic_pdi_calcule = 0
AND trafic_agrebal_calcule = 0
ORDER BY id_scenario;
 

Constitution de la file de traitement

Les scénarios identifiés sont placés dans une file de traitement interne.

Exemple :

 
12345
12346
12347
12348
12349
12350
 

Création des workers

Le batch crée :

 
NB_WORKER
 

workers de traitement.

Exemple :

 
NB_WORKER = 4
 

Création de :

 
Worker 1
Worker 2
Worker 3
Worker 4
 

Réservation des scénarios
Objectif

Garantir qu'un scénario ne puisse être traité qu'une seule fois.

Principe

Avant qu'un worker ne traite un scénario, il doit le réserver.

Le verrou métier repose sur :

 
CALCUL_TRAFIC_EN_COURS
 

présent dans :

 
TRPPU_SCENARIO
 

Réservation

Le worker tente de positionner :

 
UPDATE trppu_scenario
SET calcul_trafic_en_cours = 1
WHERE id_scenario = :idScenario
AND calcul_trafic_en_cours = 0;
 
 

Résultat
Cas 1

 
1 ligne mise à jour
 

Le scénario est réservé.

Le worker en devient propriétaire.

Cas 2

 
0 ligne mise à jour
 

Le scénario est déjà pris en charge.

Le worker passe au scénario suivant.

Traitement d'un scénario

Une fois réservé, le worker exécute successivement :

 
1. Contrôle d'éligibilité
2. Calcul des trafics PDI
3. Calcul des trafics Agrébal
 
 
 

Étape préliminaire : détermination du motif de calcul

Le batch doit déterminer le motif du calcul en consultant
TRPPU_RECALCUL_LOG.
 
Si aucune demande de recalcul n'existe pour le scénario,
le motif est considéré comme :
 
INITIAL
 
Sinon le dernier motif enregistré est récupéré :
 
AGREBAL
CLE_REPARTITION
MANUEL

Étape 1 : Contrôle d'éligibilité

Appel de :

 
controleEligibiliteScenario(idScenario)
 

US :

DSR-701 TRPPU : YB05 : Contrôle de l'éligibilité d'un scénario au calcul des trafics - DSI BSCC-Jira-Gestion des évènements projets 




Cas non éligible

Le scénario est abandonné.

Le verrou est libéré.

Le worker traite alors un autre scénario.

Étape 2 : Calcul des trafics PDI

Appel de :

 
calculTraficPdi(idScenario)
 

US :

 
DSR-702 TRPPU : YB05 : Calcul des trafics PDI d'un scénario - DSI BSCC-Jira-Gestion des évènements projets
 

Ce traitement :

 
Associe le référentiel du site
Associe la version de clés du site
Supprime les anciens trafics
Calcule les trafics PDI
Positionne TRAFIC_PDI_CALCULE = 1
 

Contrôle

Le worker vérifie :

 
TRAFIC_PDI_CALCULE = 1
 

En cas d'échec :

 
le calcul Agrébal n'est pas lancé
 

et le scénario est mis en échec.

Étape 3 : Calcul des trafics Agrébal

Appel de :

 
calculTraficAgrebal(idScenario)
 

US :

 
DSR-703 TRPPU : YB05 : Calcul des trafics Agrébal d'un scénario - DSI BSCC-Jira-Gestion des évènements projets
 

Ce traitement :

 
Contrôle la présence des trafics PDI
Agrège les trafics
Alimente TRPPU_TRAFIC_AGREBAL
Positionne TRAFIC_AGREBAL_CALCULE = 1
Positionne CALCUL_TRAFIC_EN_COURS = 0
 

Fin du traitement d'un scénario

Le scénario est considéré traité avec succès lorsque :

 
TRAFIC_PDI_CALCULE = 1
 
TRAFIC_AGREBAL_CALCULE = 1
 
CALCUL_TRAFIC_EN_COURS = 0

Journalisation des calculs et recalculs

 
Chaque calcul complet exécuté avec succès par YB05 doit être journalisé dans TRPPU_RECALCUL_LOG.
 
La journalisation est réalisée à la fin du calcul Agrébal, qui constitue la dernière étape du calcul complet.
 
Un seul enregistrement de journalisation est créé par scénario traité.
 
Le motif utilisé est déterminé à partir :
 

du dernier motif de recalcul enregistré ;
ou
de la valeur INITIAL lorsqu'il s'agit du premier calcul du scénario.

 
Les motifs possibles sont :
 

INITIAL : premier calcul d'un scénario validé ;
AGREBAL : recalcul suite évolution de la structure Agrébal ;
CLE_REPARTITION : recalcul suite activation d'une nouvelle version de clés ;
MANUEL : recalcul demandé explicitement par un utilisateur ou un exploitant.
 
Les informations enregistrées sont :
 
id_scenario ;
date du calcul ;
motif ;
commentaire.




Exemple de journalisation :
Premier calcul

 
 
ID_SCENARIO = 12345
 
RAISON = INITIAL
 
COMMENTAIRE = Premier calcul complet du scénario

Recalcul Agrébal

 
 
ID_SCENARIO = 12345
 
RAISON = AGREBAL
 
COMMENTAIRE = Recalcul complet exécuté suite évolution Agrébal

Recalcul Clés

 
 
ID_SCENARIO = 12345
 
RAISON = CLE_REPARTITION
 
COMMENTAIRE = Recalcul complet exécuté suite changement de version de clés

Recalcul Manuel

 
 
ID_SCENARIO = 12345
 
RAISON = MANUEL
 
COMMENTAIRE = Recalcul manuel du scénario

Intéraction avec YB06

 
 
Le batch YB06 est chargé d'identifier les scénarios impactés par les mouvements Agrébal.
 
Pour les scénarios concernés, YB06 :
 

crée une entrée dans TRPPU_RECALCUL_LOG ;
 
positionne :
TRAFIC_PDI_CALCULE = 0
TRAFIC_AGREBAL_CALCULE = 0
 
YB05 détecte automatiquement ces scénarios lors de son prochain lancement et exécute le recalcul complet.
Recalcul suite à évolution des clés

 
 
Lorsqu'une nouvelle version de clés devient active pour un site :
 

les scénarios impactés sont identifiés ;
 
une entrée est créée dans TRPPU_RECALCUL_LOG avec le motif CLE_REPARTITION ;
 
TRAFIC_PDI_CALCULE et TRAFIC_AGREBAL_CALCULE sont remis à 0.
 
Le prochain lancement de YB05 déclenche alors le recalcul complet du scénario.
 
Gestion des erreurs
Erreur sur un scénario

Une erreur sur un scénario ne doit jamais arrêter le batch.

Exemple :

 
Scénario 12345 -> ECHEC
 
Scénario 12346 -> SUCCES
 
Scénario 12347 -> SUCCES
 

Les autres workers continuent leurs traitements.

Libération du verrou

Quel que soit le résultat :

 
SUCCES
ou
ECHEC
 

le scénario ne doit jamais rester bloqué avec :

 
CALCUL_TRAFIC_EN_COURS = 1
 

Erreur système globale

Si une erreur empêche le fonctionnement du batch :

 
Arrêt du processus
 

Les scénarios déjà terminés restent valides.

À la fin du traitement, le batch produit un bilan global.

Critères d'acceptation
CA-01

L'exécution :

 
YB05 ALL
 

recherche automatiquement tous les scénarios éligibles.

CA-02

L'exécution :

 
YB05 ALL <id_scenario>
 

traite exclusivement le scénario demandé.

CA-03

Le nombre maximum de traitements simultanés est piloté par :

 
NB_WORKER
 

CA-04

Une valeur :

 
NB_WORKER = 1
 

produit un comportement strictement séquentiel.

CA-05

Une valeur :

 
NB_WORKER > 1
 

autorise le traitement simultané de plusieurs scénarios.

CA-06

Un scénario ne peut être réservé que par un seul worker à la fois grâce au verrou :

 
CALCUL_TRAFIC_EN_COURS
``
 

CA-07

Les traitements exécutés pour chaque scénario sont :

 
1. Contrôle d'éligibilité
2. Calcul des trafics PDI
3. Calcul des trafics Agrébal
 

CA-08

Une erreur sur un scénario ne doit pas bloquer les autres scénarios.

CA-09

Le mode ALL ne doit contenir aucune règle métier propre au calcul.

Il doit uniquement orchestrer l'exécution des traitements :

 
controleEligibiliteScenario()
calculTraficPdi()
calculTraficAgrebal()
 

CA-10

À la fin de chaque scénario traité avec succès :

 
TRAFIC_PDI_CALCULE = 1
 
TRAFIC_AGREBAL_CALCULE = 1
 
CALCUL_TRAFIC_EN_COURS = 0
 

CA-11

Le mode :

 
YB05 ALL
 
 

constitue le mode nominal d'exploitation en production et doit permettre d'adapter dynamiquement le niveau de parallélisme à la capacité du serveur via la variable d'environnement :

 
NB_WORKER
