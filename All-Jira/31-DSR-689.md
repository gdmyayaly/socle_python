


Contexte

OPTIPACC a besoin de récupérer les trafics calculés dans TRPPU afin de construire les charges de travail associées aux scénarios retenus.

Lors des échanges, il a été convenu qu'OPTIPACC ne souhaite pas reconstruire les calculs réalisés dans TRPPU ni réagréger les différentes composantes de trafic (constaté, prévisionnel, trafics manuels). OPTIPACC souhaite disposer directement du résultat final calculé par TRPPU pour chaque produit.

Le service devra donc retourner les volumes bruts consolidés par produit pour un site et un scénario donnés. 

User Story

En tant que application OPTIPACC

Je souhaite récupérer les volumes bruts calculés dans TRPPU pour un site et un scénario

Afin de disposer des trafics finaux à utiliser dans les calculs de charge sans avoir à recalculer les données métier. 

Description fonctionnelle

OPTIPACC appelle un service TRPPU en fournissant :

le code Regate du site ;
l'identifiant du scénario. 

TRPPU retourne pour ce scénario la liste des produits avec leur volume brut final. 

Règles de gestion
RG1 – Scénario concerné

Le service doit retourner les données du scénario demandé en paramètre. 

RG2 – Niveau de restitution

Le service retourne les informations au niveau Produit uniquement. 

Aucun sous-produit ne doit être retourné.

RG3 – Valeur à restituer

La valeur retournée pour chaque produit correspond au :

Volume Brut Final

calculé dans TRPPU.

RG4 – Composition du volume brut

Le volume brut correspond à la somme :

 
Constaté
+
Prévisionnel "Recalculé"
+
Trafic(s) manuel(s) éventuel(s)
 

présents en base dans la table TRPPU_TMH pour le scénario concerné.

RG5 – Calculs utilisateurs

Toutes les modifications réalisées par l'utilisateur dans TRPPU doivent être prises en compte :

ajustements du prévisionnel ;
ajouts de trafics manuels ;
corrections de trafic ;
scénarios recalculés. 

OPTIPACC doit récupérer la dernière valeur consolidée disponible. 

RG6 – Détail non retourné

Le service ne retourne pas :

les trafics constatés ;
les trafics prévisionnels ;
les trafics manuels ;
les TMH ;
les détails de calcul. 

Seule la valeur finale exploitable est transmise.

Gestion des erreurs
Cas 1 – Site inconnu
Message

Site introuvable.

Cas 2 – Scénario inexistant
Message

Scénario introuvable.

Cas 3 – Scénario non exploitable

Le scénario n'est pas dans un état permettant l'exploitation par OPTIPACC.

Message

Le scénario demandé n'est pas disponible.

Cas 4 – Erreur technique
Message

Une erreur est survenue lors de la récupération des trafics.

Critères d'acceptation
CA1

Étant donné un site et un scénario existants,

Lorsque OPTIPACC appelle le service,

Alors TRPPU renvoie la liste des produits du site avec leurs volumes bruts. 

CA2

Les volumes retournés correspondent aux volumes bruts calculés dans TRPPU.

CA3

Les trafics manuels ajoutés par l'utilisateur sont intégrés dans les volumes retournés.

CA4

Les ajustements réalisés via les paramètres de prévision sont intégrés dans les volumes retournés.

CA5

Aucun détail de calcul (constaté, prévisionnel, TMH, trafic manuel) n'est renvoyé. Seul le volume brut est transmis. 

CA6

Les codes produits retournés respectent les codifications communes validées entre TRPPU et OPTIPACC :

OS
IP
EP
PQ
autres produits validés dans la nomenclature commune. 
CA7

Le service est consumable de manière unitaire par OPTIPACC lors de la création ou de la mise à jour d'un projet. 

Notes techniques
Le calcul des volumes reste sous la responsabilité exclusive de TRPPU.
OPTIPACC consomme uniquement le résultat consolidé.
Le service doit être stateless.
Les performances attendues sont compatibles avec un appel unitaire à l'ouverture ou à la création d'un projet OPTIPACC.
