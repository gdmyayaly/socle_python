Objectif

Identifier les scénarios dont les trafics doivent être recalculés suite aux évolutions de structure des Agrébals reçues dans la journée et préparer leur recalcul par YB05.

En tant que système TRPPU

Je souhaite analyser les évolutions Agrébal reçues depuis DSR

Afin d'identifier les scénarios impactés et de les rendre éligibles à un recalcul automatique de leurs trafics par YB05.

Contexte

Le pod JS03 consomme le topic Agrébal DSR et met à jour la table :

 
TRPPU_AGREBAL_PDI
 

Lorsqu'un Agrébal :

est créé ;
est modifié ;
est supprimé ;

la répartition des trafics d'un ou plusieurs scénarios peut devenir obsolète.

Les scénarios concernés doivent être recalculés.

Le recalcul lui-même n'est jamais réalisé par YB06.

YB06 prépare uniquement les scénarios concernés.

Le calcul reste réalisé par YB05.

Déclenchement

Traitement planifié :

 
Tous les jours à 22h00
 

Horaire paramétrable.

Données utilisées
Référentiel Agrébal

 
TRPPU_AGREBAL_PDI
 

Utilisé pour identifier les Agrébals ayant évolué depuis la dernière exécution.

Scénarios

 
TRPPU_SCENARIO
 

Utilisé pour identifier les scénarios impactés.

Journal des recalculs

 
TRPPU_RECALCUL_LOG
 

Utilisé pour tracer les demandes de recalcul.

Événements pris en compte

YB06 traite les lignes dont :

 
AGREBAL_EVENT =
CREATED
UPDATED
DELETED
 

et dont :

 
AGREBAL_UPDATEDAT
 

est postérieur à la dernière exécution de YB06.

Identification des scénarios impactés

Pour chaque Agrébal modifié :

récupérer :

 
AGREBAL_CODE_REGATE
 

rechercher les scénarios du même site.
Critères de sélection

Un scénario est concerné si :

 
STATUT = VALIDE
 

et

 
TRAFIC_PDI_CALCULE = 1
 

et

 
TRAFIC_AGREBAL_CALCULE = 1
 

Scénarios exclus

Ne doivent jamais être marqués pour recalcul :

si le statut est : 

 
EN COURS
SIMULATION
EN PRODUCTION
ARCHIVE

Ou 

Que le scénario est utilisé par Optipacc, dans ce cas les scénarios ne doivent pas être pris en compte pour le recalcul.

Utiliser le même service Optipacc que celle qui vérifie dans l'IHM TRPPU si un scénario est utilisé par Optipacc avant de le repasser de Validé à "En cours" ou "Simulation." 

Traitement réalisé
Étape 1 : Création de la trace de recalcul

Pour chaque scénario impacté :

 
INSERT INTO TRPPU_RECALCUL_LOG
(
ID_SCENARIO,
DT_RECALCUL,
RAISON,
COMMENTAIRE
)
VALUES
(
:idScenario,
NOW(),
'AGREBAL',
'Demande de recalcul suite évolution Agrébal'
);
 

Étape 2 : Réinitialisation des indicateurs

Le scénario est rendu éligible à un recalcul.

 
UPDATE TRPPU_SCENARIO
SET
TRAFIC_PDI_CALCULE = 0,
TRAFIC_AGREBAL_CALCULE = 0
WHERE ID_SCENARIO = :idScenario;
 

Étape 3 : Gestion des doublons

Si plusieurs mouvements Agrébal affectent le même scénario sur une même exécution YB06 :

 
un seul recalcul doit être demandé
 

et un seul traitement du scénario est réalisé.

Relation avec YB05

YB06 ne calcule aucun trafic.

Après exécution de YB06 :

 
TRAFIC_PDI_CALCULE = 0
TRAFIC_AGREBAL_CALCULE = 0
 

Les scénarios deviennent automatiquement éligibles au traitement :

 
YB05 ALL
 

qui effectuera :

contrôle d'éligibilité ;
calcul PDI ;
calcul Agrébal ;
journalisation du recalcul réalisé.
Journalisation

YB06 journalise :

 
Demande de recalcul
 

avec :

 
RAISON = AGREBAL
 

YB05 journalise ensuite :

 
Recalcul exécuté
 

avec le même motif.

L'historique permet ainsi de conserver :

 
Date de détection
Date du recalcul effectif
Cause du recalcul
 

Gestion des erreurs

Une erreur sur un scénario :

n'interrompt pas le traitement global ;
est journalisée dans les logs techniques ;
ne bloque pas les autres scénarios.
Résultat attendu

À la fin du traitement :

les Agrébals modifiés ont été analysés ;
les scénarios impactés ont été identifiés ;
les scénarios concernés ont été marqués pour recalcul ;
une trace de la demande existe dans TRPPU_RECALCUL_LOG ;
aucun trafic n'a été recalculé directement.
Critères d'acceptation
CA-01

Étant donné un Agrébal modifié sur un site,

Quand YB06 s'exécute,

Alors les scénarios VALIDES calculés de ce site sont identifiés.

CA-02

Étant donné un scénario impacté,

Quand YB06 le traite,

Alors :

 
TRAFIC_PDI_CALCULE = 0
TRAFIC_AGREBAL_CALCULE = 0
 

sont positionnés.

CA-03

Une ligne est créée dans :

 
TRPPU_RECALCUL_LOG
 

avec :

 
RAISON = AGREBAL
 

CA-04

Les scénarios :

 
EN COURS
SIMULATION
EN PRODUCTION
ARCHIVE
 

ne sont jamais marqués pour recalcul.

CA-05

YB06 n'exécute aucun calcul de trafic.

Le recalcul reste exclusivement réalisé par :

 
YB05
 

CA-06

Si plusieurs mouvements Agrébal impactent un même scénario dans une même exécution YB06,

Alors un seul recalcul est demandé pour ce scénario.
