Objectif

Calculer les trafics PDI d'un scénario validé et figé

User Story

En tant que TRPPU,

Je souhaite calculer les trafics détaillés par PDI d'un scénario donné,

Afin de produire les données nécessaires aux calculs des trafics Agrébal et à la mise à disposition future du scénario pour Optipacc.

Commande d'exécution

Le batch doit proposer un traitement dédié :

 
YB05 CALCUL_TRAFIC_PDI <id_scenario>
 

Exemple :

YB05 CALCUL_TRAFIC_PDI 12345

ou

YB05 --traitement=CALCUL_TRAFIC_PDI --scenario=12345

Précondition

Avant tout calcul, le batch doit exécuter le contrôle d'éligibilité défini dans l'US : 
DSR-701 TRPPU : YB05 : Contrôle de l'éligibilité d'un scénario au calcul des trafics - DSI BSCC-Jira-Gestion des évènements projets
 

Le calcul ne peut démarrer que si le résultat du contrôle est :

ELIGIBLE

En cas de retour :

NON ELIGIBLE

le traitement doit être immédiatement interrompu sans aucune mise à jour de données.

Description fonctionnelle

Le traitement a pour objectif de produire les trafics détaillés :

 
PDI
Produit
Jour
Densité

pour l'ensemble du périmètre du scénario.

Le résultat est stocké dans :

TRPPU_TRAFIC_PDI

Déroulement du traitement
Étape 1 : Vérification de l'éligibilité

Appel de la fonction :

controleEligibiliteScenario(idScenario)

Résultat attendu :

 
ELIGIBLE AU CALCUL COMPLET DES TRAFICS (PDI + Agrébals)

Étape 1 BIS : Identification du type de calcul

Détermination du motif du calcul
 
Le batch doit déterminer si le traitement correspond :

à un premier calcul du scénario ;
à un recalcul suite à une évolution Agrébal ;
à un recalcul suite à une évolution des clés de répartition ;
à un recalcul manuel.
Règle

Si :
 
TRAFIC_PDI_CALCULE = 0
TRAFIC_AGREBAL_CALCULE = 0
Et qu'aucune demande de recalcul n'existe dans :
 
 
TRPPU_RECALCUL_LOG
pour ce scénario,

alors : 
 
RAISON = INITIAL
 

Sinon rechercher la dernière demande de recalcul :
 
SELECT raison
FROM trppu_recalcul_log
WHERE id_scenario = :idScenario
ORDER BY dt_recalcul DESC
LIMIT 1;
Valeurs possibles :
 
AGREBAL
CLE_REPARTITION
MANUEL
Le motif sera conservé pour la journalisation finale.
 

Étape 2 : Mise à jour du scénario

Le batch positionne immédiatement :

 
CALCUL_TRAFIC_EN_COURS = 1
 

afin d'empêcher tout lancement concurrent.

Exemple :

 
UPDATE TRPPU_SCENARIO
SET CALCUL_TRAFIC_EN_COURS = 1
WHERE ID_SCENARIO = :idScenario
 

Étape 3 : Association du référentiel et de la version de clés

 
Le batch recherche :

le référentiel actif :
SELECT id_referentiel
FROM trppu_referentiel
WHERE co_regate = :coRegate
ORDER BY id_referentiel DESC
LIMIT 1
possible aussi avec : 
SELECT id_referentiel
FROM trppu_version_cle
WHERE co_regate = :coRegate
AND actif = 'O'
la version de clés active :
SELECT id_version_cle
FROM trppu_version_cle
WHERE co_regate = :coRegate
AND actif = 'O'
ORDER BY id_version_cle DESC
LIMIT 1

Puis mémorise leurs identifiants dans le scénario.

Exemple :

 
UPDATE TRPPU_SCENARIO
SET
    ID_REFERENTIEL = :idReferentiel,
    ID_VERSION_CLE = :idVersionCle
WHERE ID_SCENARIO = :idScenario
 

Cette opération garantit la traçabilité complète des calculs.

Étape 4 : Suppression d'un calcul précédent éventuel

 
Cette étape est exécutée :

lors d'un premier calcul ;
lors d'un recalcul.
**
TRAFIC_PDI et TRAFIC_AGREBAL sont indissociables.

**
La suppression ou le recalcul des trafics d'un scénario
impose systématiquement :

la suppression des trafics PDI ;
la suppression des trafics Agrébal ;
la remise à zéro des indicateurs de calcul.
 

Par sécurité, toute donnée de trafic existante du scénario dans :

TRPPU_TRAFIC_AGREBAL

et

TRPPU_TRAFIC_PDI

doivent donc être supprimée avant recalcul :




DELETE FROM trppu_trafic_agrebal
WHERE id_scenario = :idScenario;
 

Puis : 




DELETE
FROM TRPPU_TRAFIC_PDI
WHERE ID_SCENARIO = :idScenario




Puis remettre les flags des trafics du scénario à 0 :

UPDATE trppu_scenario
SET
   trafic_pdi_calcule = 0,
   trafic_agrebal_calcule = 0
WHERE id_scenario = :idScenario;
 

Étape 5 : Chargement des données nécessaires

Le batch charge :

Données du scénario

 
ID_SCENARIO
CO_REGATE
ID_PIC_VERSION
ID_VERSION_CLE
 

TMH du scénario

Pour chaque produit.

Coefficients de rétention

Depuis :

TRPPU_PIC_COEFFICIENTS

pour :

ID_PIC_VERSION du scénario

Clés de répartition

Depuis :

TRPPU_CLE_REPARTITION_CALCULE

pour :

ID_VERSION_CLE du scénario

Mapping Agrébal / PDI

Depuis :

TRPPU_AGREBAL_PDI

pour le site du scénario.

Règle de calcul

Pour chaque combinaison :

PDI
Produit
Jour
Densité 

le batch applique :

 
TRAFIC_PDI
=
TMH
× COEFFICIENT_RETENTION
× CLE_REPARTITION_PDI
 

où :

 
TMH
=
trafic moyen hebdomadaire du produit
 

 
COEFFICIENT_RETENTION
=
coefficient issu de la version PIC du scénario
 

 
CLE_REPARTITION_PDI
=
clé du PDI correspondant au produit traité
 

Choix de la clé de répartition calculée

La clé utilisée dépend :

du produit ;
du PDI ;
de la version de clés rattachée au scénario.

Exemple :

Produit	Clé utilisée
Colis	cle_colis
OO	cle_oo
3S	cle_3s
IP	cle_potentielip
Détermination de l'Agrébal

Chaque PDI calculé doit être associé à son Agrébal.

Le batch détermine :

ID_AGREBAL

à partir du mapping :

TRPPU_AGREBAL_PDI

Alimentation de TRPPU_TRAFIC_PDI

Une ligne doit être créée pour chaque :

 
Scénario
Produit
Jour
PDI
 

avec les informations :

 
ID_SCENARIO
CO_REGATE
ID_AGREBAL

AGREBAL_UUID
ID_PDI
CO_PRODUIT
JOUR_SEMAINE
DENSE
FAIBLE1
FAIBLE2
DT_CALCUL
 

Journalisation du calcul

Créer une ligne dans :
 
 
TRPPU_RECALCUL_LOG
avec :
 
 
INSERT INTO trppu_recalcul_log
(
id_scenario,
dt_recalcul,
raison,
commentaire
)
VALUES
(
:idScenario,
NOW(),
:raison,
:commentaire
);

Exemples

Premier calcul :
 
 
RAISON = INITIAL
 
COMMENTAIRE = Premier calcul des trafics du scénario

Recalcul suite Agrébal :
 
 
RAISON = AGREBAL
 
COMMENTAIRE = Recalcul des trafics exécuté suite évolution Agrébal

Recalcul suite clés :
 
 
RAISON = CLE_REPARTITION
 
COMMENTAIRE = Recalcul des trafics exécuté suite activation d'une nouvelle version de clés

Recalcul manuel :
 
 
RAISON = MANUEL
COMMENTAIRE = Recalcul manuel du scénario----
Fin du traitement

Lorsque tous les trafics PDI ont été calculés :

TRAFIC_PDI_CALCULE = 1

et :

CALCUL_TRAFIC_EN_COURS = 1 (c'est le calcul du trafic des agrébals qui repassent ce booléen à 0)

sont mis à jour.

Exemple :

 
UPDATE TRPPU_SCENARIO
SET
    TRAFIC_PDI_CALCULE = 1,
WHERE ID_SCENARIO = :idScenario
 

Gestion des erreurs

En cas d'erreur technique ou fonctionnelle :

CALCUL_TRAFIC_EN_COURS = 0

doit être remis à jour avant la fin du traitement.

Le flag :

TRAFIC_PDI_CALCULE

doit rester à :

0
 
Si un recalcul est interrompu en erreur :
 

une ligne est créée avec un commentaire indiquant l'échec du traitement.
Par exemple : 
RAISON = CLE_REPARTITION
COMMENTAIRE = Recalcul interrompu - aucune clé de répartition trouvée
Un message significatif doit être remonté pour l'analyse du problème.

Traçabilité des calculs

Chaque exécution du calcul des trafics PDI doit être enregistrée dans la table :
 
TRPPU_RECALCUL_LOG
 
Cette journalisation permet d'identifier :
 

le scénario concerné ;
la date du calcul ;
le motif du calcul ;
le contexte du calcul.
 
Les motifs autorisés sont :
 
INITIAL
AGREBAL
CLE_REPARTITION
MANUEL 
Critères d'acceptation
CA-01

Étant donné un scénario non éligible,

Quand je lance :

YB05 CALCUL_TRAFIC_PDI 12345

Alors aucun calcul n'est réalisé.

CA-02

Étant donné un scénario éligible,

Quand le traitement est lancé,

Alors :

CALCUL_TRAFIC_EN_COURS = 1

est positionné avant le démarrage des calculs.

CA-03

Étant donné un scénario éligible,

Quand le calcul démarre,

Alors :

 
ID_REFERENTIEL
ID_VERSION_CLE
 

sont mémorisés dans le scénario avant le premier calcul.

CA-04

Pour chaque combinaison :

 
Produit
Jour
Densité
PDI
 

Alors le trafic est calculé selon :

 
TRAFIC_PDI
=
TMH
× COEFFICIENT_RETENTION
× CLE_REPARTITION_PDI
 

CA-05

À la fin du traitement :

 
TRAFIC_PDI_CALCULE = 1
CALCUL_TRAFIC_EN_COURS = 1 (car c'est le calcul du trafic des agrébals qui repassent ce booléen à 0)
 

sont positionnés dans le scénario.

CA-06

Le traitement ne doit jamais modifier :

 
STATUT
EST_FIGE
TRAFIC_AGREBAL_CALCULE
 

du scénario.

CA-07

Le traitement doit produire l'ensemble des données nécessaires au lancement ultérieur du traitement :

 
YB05 CALCUL_TRAFIC_AGREBAL <id_scenario>
``
 

qui utilisera exclusivement les données produites dans :

TRPPU_TRAFIC_PDI
 

CA-08

Étant donné un scénario jamais calculé,

Quand le calcul PDI est exécuté,

Alors une ligne est créée dans :
 
 
TRPPU_RECALCUL_LOG
avec :
 
 
RAISON = INITIAL

CA-09

Étant donné un scénario marqué pour recalcul suite à un mouvement Agrébal,

Quand YB05 exécute le calcul,

Alors une ligne est créée dans :
 
 
TRPPU_RECALCUL_LOG
avec :
 
 
RAISON = AGREBAL

CA-10

Étant donné un scénario marqué pour recalcul suite à une nouvelle version de clés,

Quand YB05 exécute le calcul,

Alors une ligne est créée dans :
 
 
TRPPU_RECALCUL_LOG
 
avec :
 
 
RAISON = CLE_REPARTITION

CA-11

Le motif utilisé pour la journalisation doit être déterminé à partir de la dernière demande de recalcul enregistrée dans :
 
 
TRPPU_RECALCUL_LOG
pour le scénario traité.
