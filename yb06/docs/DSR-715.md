Objectif

Mettre en place un nouveau POD OpenShift nommé YB06 destiné à héberger les futurs traitements d'identification des scénarios impactés par les évolutions Agrébal et de préparation des recalculs de trafics par YB05.

Cette US vise à créer le socle technique du POD. Aucun traitement métier de détection d'impacts Agrébal n'est attendu à ce stade.

User Story

En tant que TRPPU,

Je souhaite disposer d'un nouveau POD nommé YB06

Afin de fournir un environnement d'exécution dédié aux traitements de surveillance des évolutions Agrébal et aux futurs traitements Python associés.

Contexte

Les évolutions Agrébal sont transmises à TRPPU via les événements provenant de DSR et sont intégrées dans le référentiel :

TRPPU_AGREBAL_PDI

Le batch YB06 aura pour responsabilité future :

d'identifier les Agrébals modifiés ;
d'identifier les scénarios impactés ;
d'alimenter la table de traçabilité des recalculs ;
de marquer les scénarios pour recalcul ;
de préparer leur prise en charge par YB05.

Avant l'implémentation de ces traitements métier, il est nécessaire de mettre en place le composant technique YB06.

Évolutions attendues
Création du POD YB06

Créer un nouveau POD :

YB06

déployé sur OpenShift 4.

Image d'exécution

Le POD doit être basé sur une image :

Python

compatible avec les standards DSR.

Structure technique

Le POD doit permettre l'exécution de futurs traitements Python.

Il doit embarquer :

l'environnement d'exécution Python ;
les dépendances standards du projet ;
les bibliothèques de connexion à la base de données ;
les bibliothèques de journalisation ;
les composants de configuration utilisés par les autres traitements DSR.
Configuration OpenShift

Les éléments nécessaires au déploiement doivent être fournis pour les environnements :

{{DEV
ASSEMBLAGE
PREPRODUCTION
PRODUCTION}}

selon les standards du projet.

Connexion à la base de données

Le socle doit intégrer :

la lecture de la configuration de connexion ;
l'ouverture de la connexion ;
le contrôle de la connectivité ;
la fermeture correcte des ressources ouvertes.

Aucun traitement métier n'est réalisé à ce stade.

Journalisation

Le POD doit intégrer :

la journalisation applicative ;
les composants de publication vers Kibana ;
la gestion des niveaux de log.

L'ensemble des futurs traitements YB06 devra réutiliser ce mécanisme.

Point d'entrée du traitement

Le POD doit disposer d'un traitement minimal permettant :

l'initialisation du contexte ;
la vérification de la configuration ;
la vérification de l'accès à la base ;
l'émission de traces dans Kibana ;
la terminaison correcte du traitement.
Préparation des futures évolutions

Le socle YB06 doit être conçu pour accueillir ultérieurement :

Détection des impacts Agrébal

Analyse des évolutions présentes dans :

TRPPU_AGREBAL_PDI

Identification des scénarios concernés

Recherche des scénarios :

{{VALIDE
FIGE
CALCULÉS
NON EN PRODUCTION
NON ARCHIVÉS}}

Préparation des recalculs

Alimentation de :

TRPPU_RECALCUL_LOG

avec :

RAISON = AGREBAL

Marquage des scénarios

Remise à zéro de :

{{TRAFIC_PDI_CALCULE
TRAFIC_AGREBAL_CALCULE}}

afin de permettre leur recalcul ultérieur par YB05.

Hors périmètre

Cette US ne couvre pas :

l'analyse des évolutions Agrébal ;
l'alimentation de TRPPU_RECALCUL_LOG ;
la remise à zéro des indicateurs de calcul ;
les recalculs de trafic ;
les traitements YB05 ;
les traitements YB07 ;
les traitements liés aux clés de répartition.

Ces fonctionnalités feront l'objet d'US dédiées.

Règles de gestion
RG-001

Le POD YB06 doit pouvoir être déployé indépendamment des traitements métier qu'il hébergera ultérieurement.

RG-002

Le POD doit être exécutable sur les environnements OpenShift du projet.

RG-003

Le POD doit être capable d'établir une connexion à la base de données.

RG-004

Le POD doit être capable de produire des traces applicatives consultables dans Kibana.

RG-005

Toute erreur d'initialisation doit être journalisée avant arrêt du traitement.

Critères d'acceptation
CA-01

Étant donné le déploiement du POD YB06 sur l'environnement DEV

Quand le traitement est exécuté

Alors le POD démarre correctement sans erreur.

CA-02

Quand le POD démarre

Alors une connexion à la base de données est réalisée avec succès.

CA-03

Quand le POD s'exécute

Alors des traces sont visibles dans Kibana.

CA-04

Quand le traitement se termine

Alors le POD se termine proprement sans erreur.

CA-05

Étant donné le déploiement sur l'environnement ASSEMBLAGE

Quand le POD est exécuté

Alors son comportement est identique à celui observé en DEV.

Résultat attendu

À l'issue de cette US, le projet dispose d'un composant technique YB06 :

déployé sur OpenShift 4 ;
exécutable sur les différents environnements ;
connecté à la base de données ;
intégré à Kibana ;
prêt à recevoir les futurs traitements métier de détection des impacts Agrébal et de préparation des recalculs de scénarios TRPPU.
