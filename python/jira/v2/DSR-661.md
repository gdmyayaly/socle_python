En tant que TRPPU

Je veux que les informations de paramétrage de rétention en PIC soit enregistrées en base à chaque modification

Afin de conserver les changements de rétention en PIC d'un produit pour un scénario donné.

Pour cela, créer un service dans yb04 qui recevra en paramètre les informations suivantes : 

ID du scénario
Code produit pour lequel le coefficient est modifié
le jour pour lequel le coefficients est modifié
la densité > soit 0="dense", soit 1="faible 1" ou 2="faible 2"
id_rh crypté
Le service doit vérifier si une version de paramétrage PIC existe pour le scénario dans la table trppu_pic_version àl'aide de l'id_scenario recu en paramètre, puis selon le cas :

1/ Si un paramétrage spécifique au scénario existe dans trppu_pic_version il faut vérifier dans la table trppu_pic_coefficients si : 

Des lignes pour l'id_pic_version existent dans la table trppu_pic_coefficient avec le même code produit pour la même densité , alors le coefficient est mis à jour avec la nouvelle valeur ==> "update".
Des lignes pour l'id_pic_version  existent dans la table trppu_pic_coefficient mais pas pour le code produit reçu en paramètre, alors une nouvelle ligne doit être insérée dans la table trppu_pic_coefficient avec les informations suivantes ==> "insert" : 
id_pic_version
co_produit
jour_semaine
dt_effet > date courante au format datetime
coef
densite
id_rh > crypté
2/ Si aucune ligne n'existe dans la table trppu_pic_version pour le scénario alors il faut : 

insérer une nouvelle ligne dans la table trppu_pic_version avec les informations suivantes : 
lb_pic_version  > co_regate_id_scenario
niveau > 'SCENARIO' 
co_regate
id_scenario
dt_activation > date courante au format datetime
id_rh_creation > crypté
id_rh_maj > crypté (le même que l'id_rh_creation)
insérer une nouvelle ligne dans la table trppu_pic_coefficient avec les informations suivantes : 
id_pic_version  > celui qui vient d'être créé lors de l'insert dans trppu_pic_version juste avant
co_produit
jour_semaine
dt_effet > date courante au format datetime
coef
densite 
id_rh > crypté
 

L'ordre des paramètres reçus par le service doit toujours rester le même et chaque paramètre doit être "testé/vérifié" pour validation avant d'être insérer en base.

Les logs doivent tracer les appels avec les paramètres utilisés et indiquer les actions réalisées (mise à jour ou insertion) pour permettre des investigations si nécessaire.

NB : tous les logs doivent indiquer l'id session IHM afin de permettre de regrouper les traces par session IHM et faciliter les analyses.

Critère d'acceptance 

Tester l'appel du service avec tous les paramètres nécessaires pour mettre à jour le coefficient d'un produit qui existe déjà dans la table trppu_pic_coefficient pour le scénario, le même jour et la même densité. Le résultat doit être la mise à jour du coefficient uniquement.
Tester l'appel du service avec tous les paramètres nécessaires pour mettre à jour le coefficient d'un produit qui n'existe pas dans la table trppu_pic_coefficient pour le scénario mais une version "PIC" pour le scénario existe dans la table trppu_pic_version. Le résultat doit être l'insertion d'une nouvelle ligne dans la table trppu_pic_coefficient avec toutes les informations indiquées dans le 2ème cas du point 1.
Tester l'appel du service avec tous les paramètres nécessaires pour mettre à jour le coefficient d'un produit qui n'existe pas dans la table trppu_pic_coefficient pour le scénario et dont aucune version "PIC" pour le scénario n'existe dans la table trppu_pic_version. Le résultat doit être l'insertion d'une nouvelle ligne dans la table trppu_pic_version pour le scénario et l'insertion d'une nouvelle ligne dans la table trppu_pic_coefficient avec toutes les informations indiquées dans le 2ème cas du point 1 avec l'id_pic_version créé précédement.
Tester l'appel du service en omettant un ou plusieurs paramètres, le résultat est qu'aucune information n'est mise à jour ou insérer et qu'un message est tracé dans les logs et remonté à l'IHM indiquant quel paramètre est manquant.
