En tant que TRPPU

Je veux que les informations de paramétrage de rétention en PIC soit récupérées de la base  

Afin d'afficher les paramétrages de rétention en PIC propre au scénario édité.

Pour cela, créer un service dans yb04 qui recevra en paramètre l'ID du scénario pour l'utiliser afin de récupérer les paramètres de rétention PIC du scénario concerné à partir des tables trppu_pic_version et trppu_pic_coefficients.

Par défaut le système doit charger les paramètres de rétention par défaut qui sont ceux dont l'ID_PIC_VERSION vaut 1 dans la table trppu_pic_coefficients.

Puis s'il existe dans la table trppu_pic_version une ligne pour l'id scénario reçu en paramètre, il faut utiliser l'id_pic_version correspondant pour "surcharger" les paramètres par défaut avec les informations récupérés dans la table trppu_pic_coefficients dont l'id_pic_version est le même.

Les données récupérées pour cette "surcharge" annulent et remplacent les données par défaut pour le produit, le jour et la "densité" correspondante.

 

Les informations de paramètrage PIC à récupérer de la table trppu_pic_coefficients sont les suivantes : 

id_pic_version > la version du paramétrage utilisé pour récupérer les différents coefficients
co_produit > code du produit 
jour de semaine > le jour pour lequel le coefficient est utilisé 
coef > le coefficient de rétention du produit pour le jour récupéré
densite > la densité correspondant à 0 = "dense", 1 = "faible 1" et 2 = "faible 2"
=>étape 1/ toutes ces informations dont l'id_pic_version vaut 1 sont à récupérer, ce sont les paramètres par défaut.

=>étape 2/ puis toutes ces information dont l'id_pic_version correspond à celui de l'id su scénario dans trppu_pic_version sont à récupérer pour surcharger les précédentes qui correspondent

=> ie, on récupère les coefficients par défaut, puis ceux qui auraient été modifié spécifiquement pour le scénario. Ces derniers viendrons remplacer les précédents pour la clé "co_produit, jour de semaine et densite".

Les informations à récupérer de la table trppu_pic_version sont : 

id_pic_version > doit être le même que celui récupéré de la table trppu_pic_coefficients
niveau > indique si c'est un paramètrage "national", "dex", "site" ou "scenario"
une fois les données récupérées, elles sont à transmettre à l'IHM qui pourra remplir le tableau de paramétrage PIC du scénario avec.

Dans l'IHM les données seront chargées dans le table de paramétrage de rétention en PIC et celles qui auraient été modifiés seront distinguées d'une couleur différente. La distinction entre les valeurs par défaut et les valeurs "modifiées" doit pouvoir se faire sur l'id_pic_version récupéré pour chaque ligne, quand ce n'est pas celui par défaut (1) c'est que c'est une valeur modifiée pour le scénario. 

Les logs doivent tracer les appels avec les paramètres utilisés, l'id_pic_version utilisé pour récupérer les coefficients du scénario doit aussi être tracé pour permettre des investigations si nécessaire.

NB : tous les logs doivent indiquer l'id session IHM afin de permettre de regrouper les traces par session IHM et faciliter les analyses.

Critère d'acceptance 

-L'appel du service avec un id de scénario existant doit récupérer pour chaque produit leur coefficients pour chaque densité et par jour, soit 3 lignes par jour par produit sur 6 jours (du lundi au samedi).

-Pour un scénario dont les coefficients n'ont jamais été modifiés, le service récupérera tous les coefficients par défaut de niveau "national"

--Pour un scénario dont des coefficients ont été modifiés, le service récupérera tous les coefficients par défaut de niveau "national" qui n'ont pas été modifiés et ceux correspondant au scénario qui aurait été modifié.
