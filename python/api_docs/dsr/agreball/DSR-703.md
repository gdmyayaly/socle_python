Objectif
Calculer les trafics Agrébal d'un scénario à partir des trafics PDI précédemment calculés

User Story
En tant que batch YB05,

Je souhaite calculer les trafics Agrébal d'un scénario à partir des trafics PDI existants,

Afin de produire les données nécessaires à Optipacc et terminer complètement le calcul des trafics du scénario.

Commande d'exécution
Le batch doit proposer un traitement dédié :

YB05 CALCUL_TRAFIC_AGREBAL <id_scenario>

Exemple :

YB05 CALCUL_TRAFIC_AGREBAL 12345

ou

YB05 --traitement=CALCUL_TRAFIC_AGREBAL --scenario=12345

Prérequis obligatoire
Le calcul des trafics Agrébal dépend exclusivement des trafics PDI.

Par conséquent, il ne peut être exécuté que si les trafics PDI du scénario ont déjà été calculés.

Contrôle préalable
Étape 1 : Vérification de l'existence du scénario
 
SELECT *
FROM trppu_scenario
WHERE id_scenario = :idScenario;
 

Étape 2 : Vérification que les trafics PDI existent
Le batch vérifie :

TRAFIC_PDI_CALCULE = 1

dans la table :

TRPPU_SCENARIO

et qu'au moins une ligne existe dans :

TRPPU_TRAFIC_PDI

pour le scénario concerné.

Exemple :

 
SELECT COUNT(*)
FROM trppu_trafic_pdi
WHERE id_senario = :idScenario;
 

Cas bloquant
Si :

TRAFIC_PDI_CALCULE = 0

ou

Acune donnée n'existe dans TRPPU_TRAFIC_PDI

alors le traitement doit être interrompu immédiatement.

Aucun calcul Agrébal ne doit être lancé.

Message attendu
 
Calcul des trafics Agrébal impossible.
 
Les trafics PDI du scénaio 12345 n'ont pas été calculés.
 
exécuter préalablement :
YB05 CALCU_TRAFIC_PDI 12345
 
RESULTAT : ECHEC
 

Description fonctionnelle
Le calcul Agrébal consiste à agréger les trafics des PDI appartenant à un même Agrébal.

Aucune formule métier supplémentaire n'est appliquée.

Aucun coefficient n'est recalculé.

Aucune clé de répartition n'est utilisée à cette étape. 

Déroulement du traitement
Étape 1 : Suppression d'un calcul Agrébal existant
Par sécurité, les données Agrébal existantes du scénario sont supprimées avant recalcul.

 
DELETE
FROM trppu_trafic_agreal
WHERE id_scenario = :idScenario
 

Étape 2 : Lecture des trafics PDI
Le batch récupère :

 
ID_SCENARIO
ID_AGREBAL

UUID_AGREBAL
CO_PRODUIT
JOUR_SEMAINE
DENSE
FAIBLE1
FAIBLE2
 

depuis :

TRPPU_TRAFIC_PDI

Étape 3 : Agrégation des trafics
Le batch réalise une somme des trafics PDI pour chaque combinaison :

 
Scnario
Agrébal
Produit
Jour
CouleurPIC
 

Règles de calcul
Trafic Dense
 
TRAFIC_AGREBAL_DENSE
=
Σ DENSE des PDI de l'Agrébal
 

Trafic Faible1
 
TRAFIC_AGREBAL_FAIBLE1
=
Σ FAIBLE1 des PDI de l'Agrébal
 

Trafic Faible2
 
TRAIC_AGREBAL_FAIBLE2
=
Σ FAIBLE2 desPDI de l'Agrébal
 

Exemple
Données PDI
Agrébal	PDI	Dense
2404	PDI1	100
2404	PDI2	250
2404	PDI3	150
Résultat :

 
Trafic agrébal Dense
 
= 100 + 250 + 150 = 500

Alimentation de TRPPU_TRAFIC_AGREBAL

Une ligne est créée pour chaque combinaison :

Agrébal

Jour
Couleur PIC
 

avec :

 
ID_SCENARIO
CO_REGATE
ID_AGEBAL
CO_PRODUIT
JOUR_SEMAINE
COULER_PIC
VOLUME
 

Mise à jour du scénario
Une fois tous les Agrébals calculés :

 
UPDATE trppu_scenario
SET
    trafic_agrebal_calcule = 1,
    calul_trafic_en_cours = 0
WHERE id_scenario = :idScenario;
 

Fin du traitement
Le traitement Agrébal constitue la dernière étape du calcul complet des trafics.

Lorsqu'il se termine avec succès :

 
TRAFIC_PDI_CALCULE = 1
TRAFIC_AREBAL_CALCULE = 1
CALCUL_TRAFIC_ENCOURS = 0
 

Le scénario devient alors éligible à la visibilité Optipacc, conformément aux règles de statut définies. 

Gestion des erreurs
Erreur lors du calcul
En cas d'erreur :

TRAFIC_AGEBAL_CALCULE

reste à :

0

Déverrouillage du scénario
Le batch doit remettre :

CALUL_TRAFIC_EN_COURS = 0

avant de terminer.

Etat après échec
 
TRAFIC_PDI_CALCLE = 1
TRAFIC_AGREBAL_CALCULE = 0
CALCUL_TRAFIC_EN_COURS = 0

Critères d'acceptation
CA-01
Étant donné un scénario inexistant,

Quand je lance :

B05 CALCULTRAFIC_AGREBAL 12345

Alors le traitement s'arrête en erreur.

CA-02
Étant donné un scénario dont :

TRAFIC_PDI_CALCULE = 0

Quand le traitement est lancé,

Alors aucun calcul Agrébal n'est effectué.

CA-03
Étant donné un scénario dont :

TRAFIC_PDI_CALCULE = 1

Quand le traitement est lancé,

Alors les trafics Agrébal sont calculés exclusivement à partir des données de :

TRPPU_TRAFIC_PDI

CA-04
Pour chaque combinaison :

 
Agrébal
Produit
Jour
Couleur PIC
 

Le volume calculé correspond à la somme des trafics PDI associés.

CA-05
À la fin du traitement :

 
TRAFIC_AGREBAL_CALCULE = 1
CALCUL_TRAFIC_EN_COURS = 0
 

sont mis à jour dans le scénario.

CA-06
Aucune clé de répartition ni aucun coefficient de rétention ne sont utilisés lors du calcul Agrébal.

Le calcul repose uniquement sur l'agrégation des trafics PDI précédemment calculés. 

CA-07
Le traitement ne doit jamais modifier :

 
STATUT
EST_FIGE
ID_REFEENTIEL
ID_VERSION_CE
TRAFIC_PDI_CALCULE
 

du scénario.
