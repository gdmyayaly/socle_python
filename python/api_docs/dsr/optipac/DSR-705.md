Objectif

Exposer les trafics Agrébal calculés pour un scénario

Contexte

Le batch YB05 produit les trafics PDI puis les trafics Agrébal à partir :

des TMH du scénario ;
des paramètres PIC associés au scénario ;
des clés de répartition utilisées lors du calcul ;
de la structure Agrébal/PDI en vigueur. 

Les trafics Agrébal constituent le niveau de restitution nominal attendu par Optipacc. 

TRPPU doit exposer ces résultats sous forme d'API afin qu'Optipacc puisse récupérer :

l'ensemble des amas (Agrébals) d'un scénario ;
ou uniquement une liste d'amas demandés. 
User Story

En tant qu'Optipacc

Je souhaite récupérer les trafics Agrébal calculés pour un scénario

Afin de construire les simulations et les organisations de distribution.

Endpoint

POST /trafic_amas 

Requête
Body

{ "code_regate": "123456", "scenario_id": 125, "amas": [ "0bb6f27c-e4ec-42fa-a61b-f0fe6e4a1234", "77ad1e51-b9fe-490f-b9af-c1ff4f4b9876" ] }

Paramètres
code_regate

Code REGATE du site concerné.

Obligatoire.

scenario_id

Identifiant du scénario.

Obligatoire.

amas

Liste des agrebal_uuid à restituer.

Facultatif.

Si absent :

{ "code_regate": "123456", "scenario_id": 125 }

alors TRPPU retourne l'ensemble des amas calculés du scénario.

Pagination

 
Afin de limiter les volumes retournés par un appel unique, l'API supporte la pagination des résultats.

La pagination s'applique lorsque le nombre d'Agrébals à restituer dépasse un seuil configuré.

La taille maximale d'une page est pilotée par un paramètre applicatif :
 
NB_AMAS_PAR_PAGE
 
par exemple 200 ou 500 selon la configuration retenue.

Contrôles d'entrée

TRPPU doit vérifier :

C1 - Scénario existant

 
scenario_id existe 

Sinon : 
404 

C2 - Correspondance site/scénario

 
scenario.co_regate = code_regate 

Sinon : 
400 

C3 - Scénario visible

Le scénario doit respecter :

 
STATUT = VALIDE
EST_FIGE = 1
CALCUL_TRAFIC_EN_COURS = 0
TRAFIC_PDI_CALCULE = 1
TRAFIC_AGREBAL_CALCULE = 1 

conformément aux règles de visibilité Optipacc. 

Sinon : 
409 

avec le message :

{ "erreur": "Scenario non disponible" }

C4 - Vérification des amas

Si une liste d'amas est fournie :

chaque agrebal_uuid doit exister ;
chaque agrebal_uuid doit appartenir au scénario demandé.

Les UUID inconnus sont ignorés mais on trace dans le retour json et dans les logs qu'ils n'ont pas été trouvé dans trppu.

Si aucun amas valide n'est trouvé : 
404 

Données sources

Les résultats sont lus dans :

 
TRPPU_TRAFIC_AGREBAL 

table résultat produite par YB05.

Règles de gestion
RG-API-001

Seuls les scénarios visibles Optipacc peuvent être exposés.

RG-API-002

Les données retournées doivent provenir exclusivement des résultats calculés par YB05.

RG-API-003

Aucun recalcul ne doit être déclenché lors de l'appel API.

L'API est purement consultative.

RG-API-004

La clé métier d'un amas est :

 
agrebal_uuid
 

et non un identifiant technique interne.

RG-API-005

Si aucun amas n'est fourni dans la requête :

 
retourner tous les amas du scénario 

RG-API-006

Le volume retourné correspond au volume Agrébal déjà calculé.

Aucune clé de répartition, aucun coefficient PIC ou agrégat supplémentaire ne doit être appliqué pendant la restitution.

RG-API-007

Lorsque le nombre d'Agrébals à restituer dépasse la taille maximale autorisée :
 
la restitution est automatiquement paginée.
Afficher plus de lignes

RG-API-008

L'ordre de pagination doit être stable.

Les Agrébals doivent être triés par :

 
AGREBAL_UUID
 
avant pagination.

Cela garantit qu'un même Agrébal ne change pas de page entre deux appels.

Critères d'acceptation
Cas 1 – Tous les amas

Étant donné

un scénario valide et calculé

Quand

Optipacc appelle :

{ "code_regate": "123456", "scenario_id": 125 }

Alors

TRPPU retourne l'ensemble des amas du scénario.

Cas 2 – Sélection d'amas

Quand

Optipacc appelle :

{ "code_regate": "123456", "scenario_id": 125, "amas": [ "uuidA", "uuidB" ] }

Alors

TRPPU retourne uniquement les amas demandés.

Cas 3 – Scénario en cours de calcul

Étant donné

 
CALCUL_TRAFIC_EN_COURS = 1
 

Alors

l'API refuse l'appel.

Cas 4 – Scénario non calculé

Étant donné

 
TRAFIC_AGREBAL_CALCULE = 0
 

Alors

l'API refuse l'appel.

Cas 5 – Cohérence des volumes

Étant donné

les trafics présents dans TRPPU_TRAFIC_AGREBAL

Alors

les volumes restitués correspondent exactement aux valeurs stockées, sans recalcul ni transformation métier. 

Cas 6 – Scénario contenant plus d'une page d'Agrébals

Étant donné

un scénario contenant :
 
 
742 Agrébals
et :
 
 
NB_AMAS_PAR_PAGE = 200
Quand

Optipacc appelle :
 
 
JSON

{ "code_regate": "123456", "scenario_id": 125, "page": 1 }

Alors

TRPPU retourne :
 
 
les 200 premiers Agrébals
et :
 
 
JSON

{ "page": 1, "nb_pages": 4, "page_suivante": 2 }

Cas 7 – Dernière page

Quand

Optipacc demande :
 
 
JSON

{ "code_regate": "123456", "scenario_id": 125, "page": 4 }

Alors

TRPPU retourne les Agrébals restants.

et :
 
 
JSON
 
"page_suivante": null

Cas 8 – Filtre sur des UUID d'Agrébals

Si la requête contient :
 
 
JSON

{ "amas": [ "uuidA", "uuidB" ] }

la pagination n'est pas appliquée puisque le résultat est déjà limité à la liste demandée.
