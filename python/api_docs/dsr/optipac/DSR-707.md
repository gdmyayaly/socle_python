Objectif : 
Déclarer un scénario en production
Contexte

Une fois les simulations terminées dans Optipacc, un scénario est sélectionné pour devenir la référence opérationnelle de l'organisation du site.

Optipacc doit notifier TRPPU afin que celui-ci :

enregistre la date réelle de mise en œuvre ;
passe le scénario dans l'état EN PRODUCTION ;
rende le scénario définitivement figé ;
empêche toute modification ultérieure ;
empêche tout recalcul futur.

La mise en production est réalisée exclusivement depuis Optipacc.

User Story

En tant qu'Optipacc

Je souhaite notifier TRPPU qu'un scénario est mis en production

Afin que TRPPU historise cette décision et protège définitivement le scénario contre toute modification ou recalcul.

Endpoint

 
POST /scenario/mise-en-production 

Requête
Body

{ "code_regate": "123456", "scenario_id": 125, "date_mise_en_prod": "2027-04-01" }

Paramètres
code_regate

Code REGATE du site concerné.

Obligatoire.

scenario_id

Identifiant du scénario à mettre en production.

Obligatoire.

date_mise_en_oeuvre

Date effective de mise en œuvre de l'organisation.

Cette date correspond à la date de mise en production du scénario dans TRPPU.

Obligatoire.

Format :

 
YYYY-MM-DD 

Contrôles d'entrée
C1 – Scénario existant

Le scénario doit exister.

Sinon : 
404 Not Found 

C2 – Cohérence site/scénario

Le scénario doit appartenir au site demandé.

Contrôle : 

TRPPU_SCENARIO.CO_REGATE = code_regate 

Sinon : 
400 Bad Request

Message :

{ "erreur": "Le scénario <ID> n'appartient pas au site <code regate>" }




C3 – État autorisé

Seul un scénario : 

STATUT = VALIDE

peut être mis en production.

Les états suivants sont refusés :

 
EN COURS
SIMULATION
ARCHIVE
EN PRODUCTION 

Sinon :

 
409 Conflict

Message :

{ "erreur": "Les paramètres du scénario <ID> ne permettent pas la mise en production du scénario" }




C4 – Scénario calculé

Le scénario doit posséder :

 
TRAFIC_PDI_CALCULE = 1
TRAFIC_AGREBAL_CALCULE = 1
CALCUL_TRAFIC_EN_COURS = 0
 

Sinon :

 
409 Conflict
 

Message :

{ "erreur": "Les trafics du scénario <ID> ne sont pas complètement calculés" }

C5 – Unicité du scénario en production

Pour un site donné :

 
un seul scénario peut être EN PRODUCTION

Avant la mise à jour, TRPPU doit vérifier qu'aucun autre scénario du même site n'est déjà :

 
STATUT = EN PRODUCTION
 

Si un scénario est déjà en production :

 
409 Conflict 

Message :

{ "erreur": "Un scénario est déjà en production pour ce site" }

Traitement réalisé

Après validation des contrôles, TRPPU met à jour la table :

 
TRPPU_SCENARIO 

Mise à jour des champs
Statut

 
STATUT = EN PRODUCTION 

Indicateur de figement

 
EST_FIGE = 1 

Date de mise en œuvre

 
DT_MISE_EN_OEUVRE = date_mise_en_oeuvre 

Date de mise en production

 
DT_MISE_EN_PROD = date_mise_en_prod

Date de mise à jour

 
DT_MAJ = NOW() 

Réponse
Succès

 
200 OK

{ "scenario_id": 125, "code_regate": "123456", "statut": "EN PRODUCTION", "date_mise_en_oeuvre": "2027-04-01" }

Règles de gestion
RG-API-PROD-001

La mise en production est déclenchée uniquement par Optipacc.

RG-API-PROD-002

Un scénario mis en production devient définitivement figé.

Aucune modification ultérieure n'est autorisée.

RG-API-PROD-003

Un scénario mis en production ne peut plus être recalculé.

RG-API-PROD-004

Un scénario mis en production ne peut plus être supprimé.

RG-API-PROD-005

Pour un site donné :

 
un seul scénario peut être EN PRODUCTION
 

à un instant donné.

RG-API-PROD-006

La date transmise par Optipacc constitue la référence officielle de mise en œuvre et de mise en production du scénario.

Codes retour
Succès

 
200 OK 

Requête invalide

 
400 Bad Request 

Scénario introuvable

 
404 Not Found 

Conflit métier

 
409 Conflict
 

Exemples :

scénario déjà en production ;
scénario non valide ;
scénario non calculé ;
autre scénario déjà en production pour le site.
Erreur technique

 
500 Internal Server Error 

Critères d'acceptation
Cas 1 – Mise en production nominale

Étant donné

un scénario :

 
STATUT = VALIDE
TRAFIC_PDI_CALCULE = 1
TRAFIC_AGREBAL_CALCULE = 1
 

Quand

Optipacc appelle :




{ "code_regate": "123456", "scenario_id": 125, "date_mise_en_oeuvre": "2027-04-01" }




Alors

TRPPU met à jour :

 
STATUT = EN PRODUCTION
DT_MISE_EN_OEUVRE = 2027-04-01
DT_MISE_EN_PROD = 2027-04-01
 

et renvoie :

 
200
 

Cas 2 – Scénario non calculé

Étant donné

 
TRAFIC_AGREBAL_CALCULE = 0 
 

Alors

la mise en production est refusée.

Cas 3 – Scénario déjà en production

Étant donné

 
STATUT = EN PRODUCTION
 

Alors

l'API retourne :

 
409 Conflict 

Cas 4 – Un autre scénario du site est déjà en production

Étant donné

un autre scénario du même site ayant :

 
STATUT = EN PRODUCTION
 

Alors

la demande est refusée.

Cas 5 – Effet sur les traitements futurs

Étant donné

un scénario en production

Alors

toute tentative ultérieure de :

modification ;
suppression ;
recalcul ;

doit être refusée conformément aux règles de gestion TRPPU.
